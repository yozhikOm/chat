## Purpose

Чат обеспечивает обмен сообщениями в реальном времени и управление каналами: показ истории, отправку сообщений через Socket.IO, создание/переименование/удаление каналов, выбор активного канала, валидацию ввода и обработку сбоев соединения.

## ADDED Requirements

### Requirement: Загрузка истории при входе

Система SHALL загружать список каналов и сообщения через GET /api/v1/data и отображать их при переходе в аутентифицированное представление.

#### Scenario: Успешная загрузка истории

- **WHEN** пользователь входит в аутентифицированное представление (валидный токен)
- **THEN** система показывает список каналов и сообщения для текущего канала, полученные с сервера

#### Scenario: Сбой сети при загрузке истории

- **WHEN** сервер недоступен при загрузке /api/v1/data
- **THEN** система сохраняет сессию и показывает русскоязычное сообщение об ошибке сети, не разлогинивая пользователя

### Requirement: Список каналов

Система SHALL показывать в боковой панели список каналов, полученных с сервера, с выделением активного канала.

#### Scenario: Переключение канала

- **WHEN** пользователь кликает на канал в списке
- **THEN** активный канал меняется, отображаются сообщения выбранного канала

#### Scenario: Новый канал через WebSocket

- **WHEN** другой пользователь создал канал через сокет
- **THEN** новый канал появляется в списке на фронте без перезагрузки

#### Scenario: Удаление канала через WebSocket

- **WHEN** другой пользователь удалил канал через сокет
- **THEN** канал удаляется из списка; если удалён был активный — выбирается первый оставшийся канал

#### Scenario: Переименование канала через WebSocket

- **WHEN** другой пользователь переименовал канал через сокет
- **THEN** имя канала обновляется в списке

### Requirement: Создание канала

Система SHALL разрешать создание нового канала по кнопке «+», открывая модальное окно с полем ввода имени.

#### Scenario: Успешное создание канала

- **WHEN** пользователь вводит имя (2–20 символов) и подтверждает создание
- **THEN** сокет отправляет `newChannel`, канал появляется в списке и автоматически становится активным

#### Scenario: Пустое имя канала

- **WHEN** пользователь пытается создать канал с пустым именем или только пробелами
- **THEN** система показывает ошибку и не отправляет запрос на сервер

#### Scenario: Имя слишком короткое или длинное

- **WHEN** пользователь вводит имя длиной менее 2 или более 20 символов
- **THEN** система показывает клиентскую ошибку и не отправляет запрос на сервер

#### Scenario: Ошибка сети при создании

- **WHEN** сокет не отправил подтверждение (ack не получен или ошибка сети)
- **THEN** система показывает русскоязычное сообщение об ошибке; канал не добавляется в список

### Requirement: Переименование канала

Система SHALL разрешать переименование каналов с `removable: true` через модальное окно; каналы `general`/`random` (`removable: false`) переименовать нельзя.

#### Scenario: Успешное переименование

- **WHEN** пользователь меняет имя канала и подтверждает (2–20 символов)
- **THEN** сокет отправляет `renameChannel`; имя обновляется на фронте и в списке

#### Scenario: Канал не поддерживает переименование

- **WHEN** канал имеет `removable: false`
- **THEN** опция переименования недоступна; UI не показывает действие

### Requirement: Удаление канала

Система SHALL разрешать удаление каналов с `removable: true` после подтверждения; каналы `general`/`random` удалять нельзя.

#### Scenario: Успешное удаление

- **WHEN** пользователь подтверждает удаление в модальном окне
- **THEN** сокет отправляет `removeChannel`; канал удаляется из списка, его сообщения удаляются

#### Scenario: Удаление активного канала

- **WHEN** пользователь удаляет активный канал
- **THEN** активный канал переключается на первый оставшийся канал в списке

#### Scenario: Канал не поддерживает удаление

- **WHEN** канал имеет `removable: false`
- **THEN** опция удаления недоступна; UI не показывает действие

### Requirement: Отправка сообщения

Система SHALL разрешать отправку текстового сообщения в активный канал.

#### Scenario: Успешная отправка

- **WHEN** пользователь вводит текст сообщения (непустой, до 500 символов) и отправляет
- **THEN** сокет отправляет `newMessage`; сообщение появляется в панели сообщений активного канала

#### Scenario: Пустое сообщение

- **WHEN** пользователь пытается отправить пустое сообщение
- **THEN** система не отправляет его на сервер; кнопка отправки неактивна

#### Scenario: Сообщение превышает лимит

- **WHEN** длина текста превышает 500 символов
- **THEN** система показывает клиентскую ошибку; сообщение не отправляется

#### Scenario: Ошибка сети при отправке

- **WHEN** сокет не отправил подтверждение (ack не получен или ошибка сети)
- **THEN** система показывает русскоязычное сообщение об ошибке; сообщение не появляется в чате

#### Scenario: Сообщение от другого пользователя

- **WHEN** другой пользователь отправил сообщение через сокет
- **THEN** сообщение появляется в панели сообщений активного канала (если оно для этого канала)

### Requirement: Автоскролл вниз

Система SHALL автоматически прокручивать панель сообщений вниз при новых сообщениях, если пользователь не отмотал вручную.

#### Scenario: Новое сообщение внизу

- **WHEN** сообщение добавляется в конец текущего канала
- **THEN** панель сообщений автоматически прокручивается вниз

#### Scenario: Ручная прокрутка вверх

- **WHEN** пользователь прокрутил сообщения вверх вручную
- **THEN** при новом сообщении панель не прокручивается вниз

### Requirement: Обработка сетевых сбоев

Система SHALL показывать русскоязычные сообщения об ошибках при потере соединения с сокетом, не стирая сессию и не разлогинивая пользователя.

#### Scenario: Соединение с сокетом потеряно

- **WHEN** соединение сокета разорвалось
- **THEN** система показывает индикатор потери соединения, сохраняет сессию; при восстановлении подключения индикатор исчезает

#### Scenario: Восстановление соединения

- **WHEN** соединение восстанавливается
- **THEN** поток событий продолжается, индикатор ошибки скрывается
